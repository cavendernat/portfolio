MD Twin — Physician Digital Twins

An applied-AI platform concept for creating calibrated physician personas that can respond to market-research questions using structured demographic, clinical, behavioral, and feedback data.

RoleProduct strategy, UX design, system architecture, full-stack developmentMethods / toolsHTML/CSS/JavaScript · Node/Express · PostgreSQL · LLM workflows · authentication · API designPortfolio noteMD Twin was designed and built from the ground up as an end-to-end working platform.

Project mark

From concept to product

I designed and built MD Twin from the ground up, taking the product from an initial concept to a working full-stack platform. I defined the product requirements, mapped the user flows, designed the interfaces, structured the database, built the backend APIs, developed the frontend, and integrated the AI workflows. Rather than contributing to one isolated part of the system, I was responsible for how the entire product worked together, from a physician creating an account to a client receiving AI-generated market research responses.

Product & UX Design

I designed the complete experience for both sides of the platform. For physicians, I created a multi-stage onboarding and calibration process that collects clinical background, decision-making preferences, communication style, and responses to specialty-specific clinical scenarios. For clients, I designed a separate workflow for creating market research studies, selecting relevant physician personas, submitting questions, and reviewing results. I mapped these workflows before implementation and continuously refined the interfaces as the underlying system evolved.

AI Persona Architecture

I designed the system used to transform physician input into individualized AI personas. Instead of relying on a single prompt or demographic profile, MD Twin progressively builds a physician model using multiple sources of information. The system combines clinical demographics, structured preference exercises, forced-choice decisions, open-ended responses to generated clinical vignettes, and physician feedback on AI-generated answers. I designed the data pipeline that packages this information into a reusable persona that can provide responses grounded in the individual physician's documented behavior and preferences.

AI Calibration

I built a feedback loop to improve how accurately the AI represents each physician. After onboarding, the platform generates new clinical vignettes and predicts how the physician would respond. The physician then reviews those responses and identifies what the AI captured correctly and what needs improvement. That feedback becomes part of the physician's persona, allowing subsequent AI responses to incorporate both observed physician behavior and explicit corrections from the physician.

Full-Stack Development

I implemented the platform across the full application stack. I built the frontend interfaces and interactive survey components, developed the Node/Express backend and API routes that connect each stage of the workflow, and designed the PostgreSQL database used to persist physicians, clients, surveys, responses, calibration data, and generated personas. I also implemented authentication flows, dynamic survey generation, application state, data validation, and the logic connecting physician onboarding to persona creation and client research.

Database & Data Modeling

I designed the relational data model behind MD Twin. The database needed to preserve both structured survey data and complex AI-generated content while maintaining relationships between physicians, personas, calibration sessions, client studies, and research results. I created the schema and relationships that allow information collected throughout the physician workflow to be assembled into a complete persona and later retrieved when that persona is selected for a client research study.

From Prototype to Product

MD Twin required me to work across product strategy, UX research, interface design, software engineering, database architecture, and applied AI. I repeatedly moved between these disciplines as the product developed: identifying a product requirement, determining what information the system needed, designing how a user would provide it, deciding how that information should be represented in the database, implementing the interface and API, and determining how it should influence the AI. The result is an end-to-end prototype demonstrating how individual physician expertise and decision-making patterns can be translated into interactive AI personas.
